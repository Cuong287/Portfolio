## Định dạng kế hoạch bắt buộc (trả lời bằng tiếng Việt, đây là tin nhắn cuối của bạn)
1. **Hiểu yêu cầu**: 2-4 câu tóm tắt, và các giả định đã dùng.
2. **Phương án**: phương án chọn và lý do; nêu ngắn các phương án khác đã cân nhắc
   (ví dụ: xóa trước rồi di chuyển sau, hay làm đồng thời trong một task).
3. **Danh sách task theo thứ tự.** Mỗi task gồm:
   - ID và tên
   - Worker đề xuất (codex hoặc agy) và lý do
   - Phụ thuộc (task nào phải xong trước)
   - File được đọc/sửa (liệt kê cụ thể từng file/thư mục) và file ngoài phạm vi
   - Ngữ cảnh worker cần (trích từ code thật: đường dẫn, dòng, nội dung dòng)
   - Tiêu chí hoàn thành và lệnh kiểm chứng (ví dụ: `git status`, mở
     `index.html` kiểm tra ảnh hiển thị, kiểm tra không còn file rác)
   - Rủi ro
4. **Điểm cần người dùng quyết định** (nếu còn).
5. **Câu hỏi còn mở / thông tin còn thiếu.**
6. **Cách kiểm chứng tổng thể** sau khi mọi task xong (phải bao gồm: mở cả 4
   trang trong browser kiểm tra không có lỗi 404 ảnh/console error, kiểm tra
   `git status`/`git diff` chỉ đụng đúng các file trong phạm vi, xác nhận
   `logo.png`/`profile.png` không còn ở gốc, xác nhận thư mục `pbl3/` không còn
   tồn tại).

Mọi nhận định về code phải dẫn file (và dòng nếu được). Không bịa file hay hàm
không tồn tại. Chỗ không chắc, ghi rõ "chưa xác minh".
