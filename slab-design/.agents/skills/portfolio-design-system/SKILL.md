# Portfolio design system for Slab Design

## Purpose

Use the existing Portfolio as a read-only reference. Make Slab Design feel like structural engineering software in the same visual family, not another portfolio page.

## Visual DNA

- Surfaces: warm paper `#f3f0e8`, deeper paper `#e8e4da`, and restrained off-white `#fffdf7`.
- Ink: `#202522`; muted text: `#6d716c`; technical dark: `#26302c`.
- Accents: sage `#7e8c7a`, steel blue `#627a8b`, subtle yellow `#d3a926` only for numbering or precise emphasis.
- Typography: Cormorant Garamond for editorial/display headings; Inter for UI and body copy; IBM Plex Mono for symbols, units, values, metadata, and technical labels.
- Use thin `#b8bbb5` borders, sparse engineering-grid motifs, quiet texture, and generous whitespace.

## Product layout rules

- Lead each tool view with the work, input, or result—not generic dashboard chrome.
- Use open layouts and clear alignment. Group inputs by engineering meaning, not by arbitrary card count.
- Prefer technical tables, drawing-like linework, dimensional notation, and stable result hierarchies.
- Keep units next to inputs and results. Use mono type for values and notation.
- Use square or very lightly rounded controls. Focus states must be visible in steel blue.
- Treat color as semantic support, not decoration: ink for primary action, sage/steel for secondary technical states, yellow sparingly.

## Avoid

- Generic SaaS dashboards, bento grids, pill-heavy interfaces, purple AI gradients, excessive cards, glassmorphism, random icons, and template-like decoration.
- Dense boxed-in forms, unrelated visual panels, decorative effects that compete with engineering data, or ambiguous result status.

## Review checklist

- Verify the browser-rendered result on desktop, tablet, and mobile.
- Check alignment, overflow, label clipping, input/result hierarchy, focus visibility, table scroll behavior, and drawing readability.
- Preserve the calm editorial-to-technical balance: purposeful, precise, and restrained.
